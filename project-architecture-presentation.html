Padrões 1/5 Organização dos repositórios
Alibe — Padrões do projeto Branches e commits

Uma task deve ser fácil de rastrear

Nomenclatura obrigatória

Nome da branch: TASKID
Nome da MR/PR: TASKID- Nome_da_Task
  • A branch contém somente o ID da task.
  • A MR/PR combina o ID com o nome da task.
  • A branch nasce de develop e a MR/PR retorna para develop.

Conventional Commits

feat: adiciona criação de grupo
fix: corrige validação de login
chore: configura pipeline
  • feat: nova funcionalidade.
  • fix: correção de bug.
  • chore: configuração ou manutenção.
  • Referenciar a task quando ajudar na rastreabilidade.

Padrões 3/5 Task → develop → main
Alibe — Padrões do projeto Descrição da MR / PR

Como descrever uma MR/PR

Estrutura do template

## Task
Closes #123

## Tipo de alteração
[x] feature  [ ] enhancement  [ ] bugfix

## O que foi feito?
Resumo objetivo da alteração.

## Como foi feito?
Decisões técnicas e componentes alterados.

## Como testar?
Comandos e passos para validar.

Confirmações obrigatórias

  • Informar testes unitários e de integração executados.
  • Explicar migrations e alterações de seed.
  • Confirmar destino develop.
  • Para main, a origem deve ser develop.
  • Não incluir segredos, credenciais ou .env.
  • Atualizar documentação quando necessário.

O GitHub carrega esse modelo a partir de .github/pull_request_template.md. Preencha o template; não apague as seções.

Slide 3/7 Boot sequence
Route and Screen Pattern UI flow

Keep routes thin

// src/app/index.tsx
import { HomeScreen } from '@/screens/HomeScreen';

export default HomeScreen;

Good pattern

  • Route file only imports the screen.
  • Screen handles page composition and state.
  • Component library holds reusable UI pieces.

Bad pattern

  • Large layouts inside route files.
  • Business logic and UI markup mixed together.
  • Repeated markup copied across screens.

Slide 6/7 Validation
Contributor Model Workflow

How contributors work

  • Clone repository and install dependencies.
  • Create a feature branch from develop.
  • Build UI in src/app, src/screens, and src/components.
  • Run TypeScript, lint, and focused tests.
  • Open a PR targeting develop.

Branching flow

git switch develop
git pull --ff-only origin develop
git switch -c 123
# develop UI work and validate
git push -u origin 123
# open pull request to develop

This keeps feature work isolated and easy to review.

Alibe Backend Nest CLI

Gerando a base de um módulo

Geração por responsabilidade

npx nest g module modules/users
npx nest g controller modules/users/http/users --flat --no-spec
npx nest g class modules/users/application/create-user.use-case --flat --no-spec
npx nest g class modules/users/domain/user.entity --flat --no-spec
npx nest g class modules/users/persistence/prisma-user.repository --flat --no-spec

Resource completo e prévia

npx nest g resource modules/users --type rest --crud true --no-spec
npx nest g module modules/users --dry-run
  • --dry-run mostra o que seria criado.
  • --no-spec evita testes espalhados em src/.
  • O resource gera uma base, não a arquitetura final.

Depois da geração, reorganize em domain, application, http e persistence e revise o diff.

Alibe Backend Estratégia de testes

Três níveis, três perguntas diferentes

Tipo Pergunta Entrada Local e comando
Unitário A regra isolada funciona? Use case ou domínio com fake/mocks. test/unit/modules
npm run test:unit
Integração Os providers trabalham juntos? Módulo Nest, repository ou integração real. test/integration/modules
npm run test:integration
E2E A API responde ponta a ponta? Requisição HTTP com Supertest. test/e2e/modules
npm run test:e2e

Coverage: npm run test:cov mede o código de src/ exercitado pelos unitários e gera o LCOV usado pelo Sonar.

Regra prática: testar a regra no nível mais próximo e manter E2E para endpoints e fluxos importantes.

Alibe Backend CI e workflow

Validação automática antes do merge

  1. Abrir PR para develop.
  2. Qualidade, testes e build executam.
  3. Sonar analisa coverage e código.
  4. Reviewer AGES III avalia a mudança.
  5. Merge somente com checks aprovados.

Escopo atual: somente CI. Deploy/CD não faz parte desta apresentação.
